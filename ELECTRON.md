# TravlBok Desktop (Electron)

TravlBok ships as a native Windows desktop app in addition to the web app.
Every feature is preserved unchanged — Prisma, Supabase, Auth.js, dashboards,
server actions, cron routes — because the desktop app is a thin Electron
shell around the **real** production Next.js server (`output: "standalone"`).
On launch, Electron spawns that server as a local child process (bound to
`127.0.0.1:45123`) using Electron's own bundled Node runtime, waits for
`/api/health` to respond, then opens a window pointed at it. No separate
Node.js install, and no `npm run dev`/`npm start`, is required on the
end-user's machine — double-clicking the installed `.exe` is enough.

## ⚠️ Internal distribution only

`npm run electron:dist` bakes the repo's real `.env` (live Supabase
`DATABASE_URL`/`DIRECT_URL`, `AUTH_SECRET`, and any configured Stripe/PayPal/
Resend/S3 keys) into the packaged app so it works out of the box with zero
setup. That means **the installer and the installed app both contain live
production credentials in plain text on disk** (`resources/standalone/.env`
next to the installed `TravlBok.exe`).

This is an accepted, deliberate tradeoff for this build — approved on the
basis that the app is only ever installed by the trusted internal team.

- **Do not** upload the installer to any public location, ticket, Slack
  channel outside the team, cloud drive with broader sharing, or GitHub
  release/artifact.
- **Do not** commit `release/` or `.next/standalone/.env` — both are
  gitignored; keep it that way.
- If the installer needs to go to anyone outside the immediate trusted team,
  stop and switch to an external-config distribution model instead (see
  "Alternative: external config" below) rather than sending this build.
- If a machine running the installed app is ever lost, stolen, or
  decommissioned, rotate `AUTH_SECRET` and the Supabase DB credentials.

## Building the installer

```bash
npm run electron:dist
```

This runs, in order:
1. `next build` — production build of the Next.js app (`.next/standalone` +
   `.next/static`).
2. `scripts/prepare-electron.js` — copies `public/` and `.next/static/` into
   `.next/standalone` (Next's standalone tracing doesn't include them by
   default — same requirement as the Docker build), and writes a runtime
   `.env` into `.next/standalone/.env` with `AUTH_URL` /
   `NEXT_PUBLIC_APP_URL` overridden to `http://127.0.0.1:45123` (everything
   else copied through as-is from the repo's `.env`).
3. `electron-builder` (NSIS target) — packages `electron/`, plus
   `.next/standalone` as `extraResources`, into a Windows installer at
   `release/TravlBok-Setup-<version>.exe`.

The installer lets the user pick an install directory, and creates Desktop
and Start Menu shortcuts (`electron-builder.yml` → `nsis`).

### Quick iteration without a full installer

```bash
npm run electron:pack   # unpacked app under release/win-unpacked/ — faster, for local testing
npm run electron:dev    # builds, then launches Electron directly (no packaging step at all)
```

### Regenerating the app icon

`build-assets/icon.ico` / `icon.png` were generated by `scripts/generate-icon.js`
(a placeholder "TB" monogram badge — no branding asset existed in the repo).
Replace the files in `build-assets/` directly with real artwork whenever
proper icons are designed; `npm run electron:icon` re-runs the generator if
you ever need to regenerate the placeholder.

## How auto-start works (`electron/main.js`)

- On `app.whenReady()`, spawns `node.exe`-equivalent
  (`process.execPath` with `ELECTRON_RUN_AS_NODE=1`) running
  `.next/standalone/server.js`, with `PORT=45123`, `HOSTNAME=127.0.0.1`,
  `NODE_ENV=production`.
- Polls `http://127.0.0.1:45123/api/health` (the same real DB-connectivity
  health check used by the Docker `HEALTHCHECK`) until it responds, up to 45s,
  before loading the window — avoids a blank/error window on a slow first
  start.
- A single-instance lock prevents a second launch from spawning a conflicting
  second server on the same port; re-launching just focuses the existing
  window.
- The embedded server is killed on `before-quit`; if it exits unexpectedly
  while the app is open, the user gets an error dialog instead of a silently
  dead window.
- External links (anything not on `127.0.0.1:45123`) open in the user's real
  browser via `shell.openExternal`, never inside a bare Electron window.

## Alternative: external config (for wider distribution later)

If this app ever needs to be installed by anyone outside the current trusted
team, do not reuse this build as-is. Instead: strip the `.env` bundling step
out of `scripts/prepare-electron.js`, and have `electron/main.js` read
configuration from e.g. `%APPDATA%/TravlBok/.env` (created via a first-run
setup screen), refusing to start the embedded server until it's present.
That keeps no secrets inside the distributed installer at all.
